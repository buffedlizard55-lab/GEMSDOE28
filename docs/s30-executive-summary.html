  • It is a strict subset of the GEMSDOE31 H27-4 solo-d28 field. That parent has 40,199 dots (USER-REPORTED 0.2708). Exactly 2,545 of its dots are absent from the 0.2778 file; no dot is added. Each removed dot lies within 2 px of a catalogue fault (median distance 2.0 px, maximum 2.0 px).
  • So the +0.0070 gain is a pruning effect. The change removes catalogue-adjacent predictions and nothing else. Under the official metric (α = 0.2 false-positive weight, β = 0.8 false-negative weight, 300 m triangular kernel), a dot that sits next to known faults is more likely to be a false positive for the new-fault truth. Removing it cuts α-weighted false-positive mass and loses little recall. The sign is consistent with that; the size cannot be computed without the hidden truth.
  • The family plateau. Across the nine named sites the reported scores fall within 0.2449–0.2778, all from dot fields of roughly 37k–61k points. The field, not any single trick, sets the plateau.
  • Caveat. The 0.2708 and 0.2778 numbers are user-reported public-board values. No organizer receipt ties either number to either file.

How the S30 candidate was made

  1. Start from the GEMSDOE32 H33-2-B2 dots (the 0.2778 file).
  2. Keep the 65% of those dots that lie farthest from the USGS/INGENIOUS catalogue. Remove the other 35%. The removed dots sit at median 6.0 px from the catalogue (maximum 12.0 px). The kept dots start at 12.0 px.
  3. Refill with 13,179 new dots. These sit at median 28.8 px from the catalogue, at ≥ 6 px, placed greedily along reduced-to-pole magnetic ridges (the training-feature band rtp, 1.5 px smoothing) with 4 px spacing.
  4. Uniqueness budget. For each of the 472 registry rasters, the candidate's running overlap is capped at 68%. The cap is enforced during placement, not only checked afterwards.
  5. Write with the shared writer (src/gems27/submission.py), zeros outside, float32, and re-read the bytes.

Honest limits. Two-thirds of the candidate's dots are the 0.2778 file's dots. The budget guarantees the gate, not a score. The 35% replaced dots were removed for uniqueness, not because the evidence shows they are false positives beyond the 2-px band. The gain or loss is unknown.

Official rules this page relies on (verified 2026-10-30)

  • Problem description: DTI metric, α = 0.2, β = 0.8, 300 m triangular kernel. Predictions are probabilities in [0, 1]. Outside the bounds, "data is null or nan". The file must be a single float32 layer on EPSG 32611 at 100 m.
  • Public leaderboard (read 2026-10-30, ranks 1–23): #1 0.4544, #2 0.3925. The board is sorted by score, so 0.4413 does not appear. The 0.3195 figure was not in the ranks read.
  • Scoring is in two rounds. The Initial Prize Round is ranked on a private set. The Final Prize Round rescores against expert-verified new faults, which rewards predictions that find faults nobody else has mapped. That makes uniqueness relevant to the prize.
  • Rules PDF and reference solution are the owner's cited sources.

Irregularities flagged for review

  • Portal error "Predicted values must be in range [0, 1]". The root cause is not known. Every named file has all in-footprint values in [0, 1]. The official text allows NaN outside the bounds, so the NaN variants are in spec. Zeros outside are also inside the raster bounds and in range. The error may come from a different file, or from a rule the portal enforces that is not public.
  • Catalogue masking is unverified. The repository assumes known catalogue pixels are masked (neither credit nor cost). The official page does not say so. If the portal does not mask them, every dot on a catalogue pixel is a false positive. The nine named files and the S30 candidate place zero dots on the catalogue; 29 of the 475 registry rasters do place dots there.
  • Leaderboard figures conflict. The prompt cites 0.4413 as the leader. The public board read on 2026-10-30 is sorted by score: #1 is 0.4544 and #2 is 0.3925, so 0.4413 does not appear. The 0.3195 figure does not appear in ranks 1–23 read this session; it was not located.
  • Data-provenance note. The H33-2 hypothesis cites MT conductance (ScienceBase) in the pinned-layer registry. The 0.2778 artifact is a pruning of the H27-4 solo field and uses none of those layers. The label is misleading.
  • Format variance. Across 475 registry rasters, the audit found 223 NaN-outside, 246 zeros-outside, 5 mixed encodings, 1 off-grid test file (GEMS36_FORMAT_TEST_NOT_SUBMISSION.tif), and 1 raster with NaN inside the footprint (gemsdoe31-csdu-stepover-8cf9dc27-nan.tif). That NaN-inside file is a candidate cause to test, not a confirmed one. Full list: evidence/s30_registry_audit.json.
  • Files labelled DO-NOT-SUBMIT or research-only are in the registry, for example gems31-tgj31-transfer-20261025-8d912b23db-DO-NOT-SUBMIT.tif. They were included in the uniqueness check, which makes the check stricter.
