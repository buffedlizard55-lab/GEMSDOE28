Why does the supplied GEMSDOE32 result lead?

Verified construction, not verified score causation: the freshly fetched GEMSDOE32 raster is exactly the GEMSDOE31 solo dot set with 2,545 catalogue-adjacent dots (distance ≤2 px) removed. It has 37,654 dots. GEMSDOE25 and GEMSDOE30 have exactly the same historical dot geography; GEMSDOE36 contains every champion dot plus 1,200 extras. These are pixel-forensic counts, not new model results.

The shared evaluator uses a 300 m triangular distance kernel and DTI = TPw / (TPw + 0.2 FPw + 0.8 FNw). Closely packed predictions can be redundant for credit but still add false-positive mass. Pruning low-marginal-credit dots can therefore improve a result without detecting a single new fault. That mechanism is consistent with the supplied ladder; hidden truth and file-bound organizer receipts are absent, so the actual cause of the reported ranking is not established.

Can we honestly claim a file above the reported 0.2778? No. A distinct detector might improve coverage, but this session did not validate one. No credible leaderboard point estimate or interval is available for a new TIFF.
