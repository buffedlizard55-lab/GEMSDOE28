Exactly how submission will work once approved

  1. Generate a genuinely new lane-specific surface using the shared cached stack. Run per-feature leakage canaries; AUC above 0.90 blocks trust until explained. Check registry similarity before placing dots; stop on duplicates.
  2. Hide whole fault segments with a buffer; rebuild catalogue features from visible faults only and mask visible faults pixel-exactly. Use the shared evaluator (alpha 0.2, beta 0.8, 300 m triangular kernel). Beat the frozen comparable best under the predeclared paired gate.
  3. Check final-dot uniqueness, then use the shared writer and validate the exact final bytes: one band, finite inside footprint, values in [0,1], matching CRS, shape and transform. Check actual values as well as nodata metadata; never use numeric missing-value sentinels as probabilities.
  4. Publish a content-addressed TIFF link, SHA-256, unique submission name and note of at most 140 characters only after all required gates pass. Currently no such file is approved.
  5. A separate selector checks the authenticated weekly allowance. Upload the approved TIFF (or a ZIP containing only that TIFF), paste its identifying note, and retain the submission-page receipt.
